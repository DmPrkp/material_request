# warehouse-server

Склады пользователей. NestJS + Drizzle, порт 4400, префикс `/warehouse/api/v1`, база `warehouse`.
Каркас взят у dictionary-server (гвард, фильтр ошибок pg, пагинация, миграции), но без
Scalar/OpenAPI и без локализации — клиента у сервиса пока нет.

## Доступ

Всё закрыто глобальным `AuthGuard` (`src/auth/`). Токен user-server проверяет nginx
(`nginx/njs/auth.js`) и передаёт пользователя заголовками `X-User-Id` / `X-User-Role` — сервис
секрета не знает. Без входа — `401`; битый токен и отсутствие секрета у nginx (`401` / `503`)
до сервиса не доходят. Поэтому на проде порт сервиса наружу не опубликован.

Склад принадлежит тому, кто его завёл (`owner_id` = `sub`, из тела не принимается — лишнее поле
даёт `400`). Список — только свои, у админа тоже; по id админ достаёт и правит любой. Чужой
склад остальным — `404`, а не `403`.

## API

| Метод    | Путь                      | Что делает                                                      |
| -------- | ------------------------- | --------------------------------------------------------------- |
| `GET`    | `/warehouses`             | свои склады; `?page`, `?limit`, `?q` (название/адрес), `?state` |
| `GET`    | `/warehouses/:id`         | один склад                                                      |
| `POST`   | `/warehouses`             | `{ name, address?, description? }`                              |
| `PATCH`  | `/warehouses/:id`         | те же поля, любые; `""` стирает необязательное                  |
| `DELETE` | `/warehouses/:id`         | мягко (`is_active = false`), `?hard=true` — физически           |
| `POST`   | `/warehouses/:id/restore` | вернуть архивный                                                |

Название уникально у владельца без учёта регистра среди действующих: дубль — `409`,
как и восстановление архивного при живом тёзке.

## База

Схема — `src/db/schema.ts`, миграция — `drizzle/0000_init.sql` (`npm run db:generate`; пока
проект не развёрнут, миграция одна — перед генерацией удалить `drizzle/`). `npm run db:migrate`
сам заводит базу, если её нет: `db/init` срабатывает только на пустом томе, а на проде
Postgres внешний. Нет прав на `CREATE DATABASE` — базу надо завести руками.

Env — `secrets/warehouse-db/.db.env` в том же формате, что у словаря (`POSTGRES_DB=warehouse`).
