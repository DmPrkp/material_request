# company-server

Компании пользователей. NestJS + Drizzle, порт 4500, префикс `/company/api/v1`, база `company`.
Каркас — от warehouse-server (а тот — от dictionary-server): гвард, фильтр ошибок pg, пагинация,
миграции. Без Scalar/OpenAPI и без локализации — клиента у сервиса пока нет.

## Доступ

Всё закрыто глобальным `AuthGuard` (`src/auth/`). Токен user-server проверяет nginx
(`nginx/njs/auth.js`) и передаёт пользователя заголовками `X-User-Id` / `X-User-Role` — сервис
секрета не знает. Без входа — `401`; битый токен и отсутствие секрета у nginx (`401` / `503`)
до сервиса не доходят. Поэтому на проде порт сервиса наружу не опубликован.

Не участник компании её не видит: и компания, и её участники отвечают `404`, а не `403`.
Список — только компании, где спрашивающий участник, у админа тоже; по id админ (`ADMIN` в
токене) видит и правит любую, как владелец.

## Участники и роли

Участник — строка `company_members` (`company_id`, `user_id`, `roles[]`), в той же базе, что
компания: создание компании с владельцем и любая правка состава — одна транзакция, без саги.
`user_id` — id из user-server, без FK и без проверки, что такой пользователь есть.

Роли: `own` (владение), `manage` (управление), `review` (проверка), `store` (хранение); у
участника их может быть несколько. Создатель компании получает `own` автоматически.

| действие                     | own | manage | review / store |
| ---------------------------- | --- | ------ | -------------- |
| видеть компанию и участников | да  | да     | да             |
| переименовать                | да  | да     | —              |
| удалить компанию             | да  | —      | —              |
| выдать/снять review, store   | да  | да     | —              |
| выдать/снять own, manage     | да  | —      | —              |
| выйти самому                 | да  | да     | да             |

Проверяется только то, что меняется: управляющий может добавить `store` владельцу, не трогая
его `own`. Последнего владельца не снять и не удалить — `409 last_owner`: сначала передать `own`
другому. Правки состава одной компании идут по одной (строка компании под `FOR UPDATE`), иначе
два владельца, одновременно снимающие друг друга, оставили бы компанию без владельца.
Правила — `src/modules/companies/roles.ts`, тесты — `companies.spec.ts`.

## API

| Метод    | Путь                             | Что делает                                               |
| -------- | -------------------------------- | -------------------------------------------------------- |
| `GET`    | `/companies`                     | мои компании с моими `roles`; `?page`, `?limit`, `?q`    |
| `GET`    | `/companies/:id`                 | одна компания с моими `roles`                            |
| `POST`   | `/companies`                     | `{ name }`, создатель получает `own`                     |
| `PATCH`  | `/companies/:id`                 | `{ name? }` — own, manage                                |
| `DELETE` | `/companies/:id`                 | удалить вместе с участниками, `204` — own                |
| `GET`    | `/companies/:id/members`         | участники: `userId`, `roles`, `createdAt`, `updatedAt`   |
| `PUT`    | `/companies/:id/members/:userId` | `{ roles: [...] }` — добавить или заменить набор целиком |
| `DELETE` | `/companies/:id/members/:userId` | убрать участника (свой id — выйти), `204`                |

Пустой `roles` в `PUT` — `400`: убирают участника `DELETE`, а не снятием всех ролей.
Название компании обязательно (1–200 символов после обрезки пробелов), уникальность не проверяется.
Удаление компании физическое.

## База

Схема — `src/db/schema.ts`, миграция — `drizzle/0000_init.sql` (`npm run db:generate`; пока
проект не развёрнут, миграция одна — перед генерацией удалить `drizzle/`). `npm run db:migrate`
сам заводит базу, если её нет: `db/init` срабатывает только на пустом томе.

Env — общий `.env` в корне (`.env.example`), `POSTGRES_DB=company` задан в compose.
